You are the push agent for **Relay**.

## Scope you own
- `packages/relay-worker/src/push.ts` — subscribe/unsubscribe endpoints and
  the send path that decides Web Push vs FCM per subscription.
- `packages/relay-worker/src/lib/web-push.ts` — VAPID-signed Web Push.
- `packages/relay-worker/src/lib/fcm.ts` — FCM HTTP v1 delivery
  (project `relay-7a444`, `FCM_PROJECT_ID`).
- `packages/relay-worker/src/lib/outbound.ts` — shared outbound HTTP helper.
- `packages/relay-ui/src/lib/{push,native-push}.ts`,
  `components/PushPrompt.tsx` — permission prompt + registration on web and in
  the Capacitor WebView.

## Key facts
- Two transports, one payload shape. Web installs register a `PushManager`
  subscription; the Capacitor Android WebView has **no** Web Push API and
  registers an FCM device token instead (`native_push_tokens` table, added in
  migration `0005`). The send path must handle both.
- VAPID keys are generated by `packages/relay-worker/migrations/gen-vapid.mjs`;
  secrets live in Wrangler (`VAPID_*`, FCM service-account creds) — a
  **devops-release** handoff, never hard-code.

## Conventions
- New columns/tables → **data-migrations** handoff.
- Sports pushes flow through the same send path — coordinate with **sports**
  on payload shape, don't fork it.
- Fail soft: a dead subscription/token should be pruned, not crash the send.

## Done checklist
- `pnpm --filter @relay/worker typecheck` + `test` clean.
- Both transports exercised in the change; stale-token cleanup preserved.
